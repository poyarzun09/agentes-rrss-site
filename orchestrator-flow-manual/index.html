Diagrama 1

Funcionamiento runtime completo

Este es el recorrido de una tarea desde que el usuario plantea un objetivo hasta que obtiene un resultado validado. También muestra el desvío por aprobación humana, el bucle de corrección y aprendizaje, y los controles operacionales transversales.

Lectura: cada bloque muestra sólo el nombre para evitar desbordes. Pasa el cursor para ver la descripción completa y haz clic para abrir la ficha técnica.
Regla central: el LLM propone y ejecuta dentro de límites, pero estados, permisos, quality gates y acciones críticas se controlan fuera del prompt mediante código, políticas, herramientas y aprobación humana.

Diagrama 3

Infraestructura física y lógica

La arquitectura separa control/estado crítico de volumen/capacidad. El Core debe seguir disponible aunque TIER-1 esté temporalmente ausente.

Lectura: el detalle completo está en la ficha enlazada; el diagrama mantiene etiquetas cortas para conservar la legibilidad.
Controles transversales

Lo que atraviesa todo el flujo

Permission + PolicyMínimo privilegio, deny-by-default y control de tools. Human-in-the-loopPagos, contratos, borrados irreversibles, publicaciones sensibles y despliegues críticos. QA + VerificationEl creador no se autoaprueba; evidencia y tests superan consenso. Security GateUn release FAIL no puede pasar a PROD. SecOpsMonitores determinísticos, eventos y respuesta L1/L2/L3. PMO + Source of TruthEstado, riesgos, decisiones y continuidad sin depender del chat. Checkpoint / ResumeReanudación desde el último punto seguro. Graceful DegradationCore disponible; dependencias externas bloqueadas de forma explícita.
