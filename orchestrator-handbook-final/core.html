Orchestrator Agéntico Local v4.0

Orchestrator Agéntico Local v4.0

Es el sistema central que vamos a construir desde cero en el Mac Studio para convertir solicitudes del usuario en trabajo coordinado entre equipos de agentes. El Orchestrator decidirá qué equipo participa, qué agentes se activan, qué herramientas pueden usar, cómo se verifica el resultado y cómo queda registrado para poder continuar después.

ID root14 subfuncionesTO-BE v4.0

Objetivo

Convertir objetivos del usuario en trabajo coordinado entre equipos de agentes, con permisos, verificación, trazabilidad y continuidad.

Nivel de definición

Definición funcional suficiente para diseño. Implementación y contratos exactos siguen TO-BE.

Responsabilidades

  • Baseline v4.0: arquitectura greenfield y almacenamiento por niveles; no parte del código del Orchestrator actual.
  • Host inicial: Mac Studio M1 Max, 32 GB de memoria unificada.
  • Estrategia: operación local, evidencia antes que afirmaciones y calidad por sobre velocidad.
  • El Orchestrator existente queda intacto. Sólo podrá consultarse para rescatar una idea útil; cualquier función reutilizada se rediseñará e implementará nuevamente bajo la arquitectura v4.0.

Flujo funcional

El usuario define un objetivo→Task Manager registra el trabajo→Planner lo descompone y selecciona equipo→Scheduler espera recursos y dependencias→Workflow Engine ejecuta steps y gates→Context Manager arma el contexto→Agent Runtime activa el rol lógico→Model/Tool Gateway ejecutan IA y herramientas→Verification + QA comprueban evidencia→Learning/Audit/PMO registran resultado y continuidad→Se entrega resultado validado al usuario

Objetivo

Cumplir la responsabilidad descrita para «2. Arquitectura central del Orchestrator» de manera explícita, verificable y desacoplada del resto del sistema.

Nivel de definición

Definición funcional suficiente para diseño. Implementación y contratos exactos siguen TO-BE.

Responsabilidades

  • Cada módulo tendrá responsabilidad y contrato definidos para que pueda probarse y evolucionar sin acoplar todo el sistema.
  • Las tareas, agentes y aprobaciones sólo podrán pasar entre estados permitidos por código; no dependerán de texto libre generado por el LLM.
