Context Manager

Componente TO-BE que entrega al modelo sólo el contexto necesario y confiable, bajo un presupuesto y una prioridad explícitos.

TO-BERF-024RNF-010Sin cuotas numéricas inventadas

Component / Context engineering

Diseño v4.0
Objetivo fuente
Entregar al modelo sólo el contexto necesario y confiable.

Problema que resuelve

Evita cargar repositorios completos, memoria histórica completa, documentos irrelevantes o duplicados. La calidad tiene prioridad sobre velocidad, pero se deben evitar ejecuciones redundantes.

Presupuesto de contexto documentado

El Context Manager asignará espacio a:

system prompttarearequisitosartifactsmemoryevidencetool resultsresponse budget
No hay números en la baseline. Cualquier porcentaje o cantidad de tokens debe quedar pendiente de benchmark; no se inventa.

Orden de prioridad

  1. Reglas y políticas.
  2. Requerimiento actual.
  3. Evidencia.
  4. Estado de tarea.
  5. Memoria relevante.
  6. Material complementario.

Entradas conocidas

  • System prompt.
  • Tarea/requerimiento.
  • Requisitos.
  • Artifacts relevantes.
  • Memoria relevante.
  • Evidencia.
  • Resultados de tools.

Salida

SPECIFICATION GAP: la baseline define el propósito y categorías del contexto, pero no el schema formal del “context package” entregado al Agent Runtime / modelo.

Proceso que sí está soportado por la fuente

  1. Recibir tarea/requerimiento y contexto disponible.
  2. Aplicar prioridad: políticas y requerimiento antes que material complementario.
  3. Seleccionar memoria y evidencia relevantes.
  4. Excluir repositorios completos sin filtrado, memoria histórica completa, documentos irrelevantes y duplicados.
  5. Asignar el presupuesto de contexto entre las categorías documentadas.
  6. Reservar response budget.
  7. Entregar un contexto acotado al runtime/modelo.

State model

No existe una state machine propia para Context Manager en la baseline. No se muestra una sección de estados heredados porque eso sería confundir Task/Agent state con estado interno del componente.

Errores

No hay códigos exclusivos de Context Manager. El estándar global contempla CONFIG_ERROR, RESOURCE_EXHAUSTED, DATA_INTEGRITY_ERROR e INTERNAL_ERROR, pero la asignación exacta a este componente está pendiente.

Resource Manager

La baseline general exige administrar recursos de inferencia mediante Resource Manager. No existe en el documento de Context Manager un contrato formal que especifique cómo ambos intercambian presupuesto.

Seguridad

Los datos internos deben permanecer localmente salvo acción explícita y los secretos deben permanecer fuera de prompts. La clasificación/manejo específico de cada fragmento no está definido dentro de esta ficha fuente.
