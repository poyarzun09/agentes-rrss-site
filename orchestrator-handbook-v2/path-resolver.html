Path Resolver

Único punto autorizado para resolver rutas críticas desde roots configurados, verificar identidad del almacenamiento externo y evitar paths hardcodeados.

TO-BERF-055RF-056ADR-007Task técnica #18

Identidad

Entidad v2
CORE.COMPONENT.PATH_RESOLVER
Tipo
Component / Infrastructure boundary
Estado
Baseline para implementación
Roots
ORCH_LOCAL_ROOT · ORCH_EXT_ROOT

Objetivo fuente

Evitar rutas absolutas dispersas en código. Modelos, artifacts, projects y knowledge se resuelven desde un único servicio PathResolver.

Reglas obligatorias

  • Ningún agente construye rutas críticas manualmente.
  • Paths se normalizan antes de uso.
  • Traversal fuera de roots autorizados debe impedirse.
  • Configuración dependiente del entorno.
  • Tests para paths ausentes, read-only y mount cambiado.
  • No hardcodear el nombre del volumen.
  • No trasladar silenciosamente datos del externo al interno para “resolver” un fallo.

Preflight del SSD externo

  1. Comprobar que ORCH_EXT_ROOT existe.
  2. Verificar que es el volumen/mount esperado.
  3. Comprobar el marker .orchestrator-volume-id.
  4. Comparar el contenido del marker con la configuración.
  5. Comprobar escritura cuando la tarea la necesita.
  6. Comprobar espacio libre suficiente.

Estados de health documentados

  • EXTERNAL_STORAGE_HEALTHY
  • EXTERNAL_STORAGE_READ_ONLY
  • EXTERNAL_STORAGE_LOW_SPACE
  • EXTERNAL_STORAGE_MISSING
  • EXTERNAL_STORAGE_IDENTITY_MISMATCH

Regla de seguridad

Ante mismatch de identidad el sistema no debe escribir y debe bloquear tareas dependientes.

Entrada

La política habla de una ruta lógica/resolución desde roots, pero no define un PathRequest schema ni firma de API.

Salida

La semántica esperada es una ruta resuelta válida o un error/health explícito. El objeto de respuesta formal no está especificado.

Modo degradado relacionado

Si falta TIER-1, Core permitido: UI, PMO, DB, config, estado, audit, revisión de tareas y health diagnostics. Se bloquean inferencia dependiente del externo, knowledge/proyectos/artifacts externos y multimedia.

Errores

Se aplican clases globales como CONFIG_ERROR, PERMISSION_ERROR y DATA_INTEGRITY_ERROR según corresponda; la baseline no define códigos propios de PathResolver.
